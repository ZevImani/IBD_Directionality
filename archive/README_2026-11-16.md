# emd_paper: Paper C directional-reconstruction analysis

The code and results come from Max A. A. Dornfest (Univ. of Hawai'i, FROST collaboration, "Paper C"). They were transferred from mtc-b and
integrated here on 2026-11-16. The topic is IBD directionality in segmented detectors. The analysis compares the angular resolution of **Centroid**, **FND**
(Frobenius-norm template matching) and **EMD / W1** as a function of segment pitch `dx` (5/50/150 mm on a 450 mm face), usable events `N`,
total exposure `n_total`, smearing, and sparsity `rho = N/G^2`.


Environment: `conda activate ldm` (Python 3.8). `astropy` 5.2.2 was installed on 2026-11-16. Optional packages that are not installed: `mpi4py` and `pycircstat2`.
Without pycircstat2, the Watson U² columns come out as NaN.

**Plotting requires `LD_LIBRARY_PATH=$CONDA_PREFIX/lib`.** Without it, matplotlib/PIL fail with `GLIBCXX_3.4.29 not found`, because the system libstdc++ is too old. Example:
`cd code && LD_LIBRARY_PATH=$CONDA_PREFIX/lib MPLBACKEND=Agg python plot_final_paper_figures_v3_0.py`

Plotting scripts only read existing tables in `results/tables/`, so they run in seconds anywhere. Only the `run_*` sweeps need a compute node.
Local change to Max's code (2026-11-16): the 9 figure-producing scripts save to `PLOT_DIR` instead of `review_deliverables/`. Nothing else was changed,
so `diff` against `archives/paperC_zev_claude_pkg.tar.gz` shows exactly this edit.

## Figures of merit

All of these are built from the spread of the reconstructed angle over K independent trials, `sigma_theta`, for each estimator, pitch and N.

| FoM | Definition | What it answers | Source table |
|---|---|---|---|
| **Θ (normalized resolution)** | `sigma_theta * sqrt(N_usable)` [deg·√events] | Estimator quality independent of N. It is flat in the asymptotic regime, so one number describes each (estimator, pitch). | production_exposure, unclipped_scaling |
| **Statistical efficiency η** | `(Θ0,cut / Θ)^2`, with `Θ0,cut = sigma_perp/r_bar` of the *post-cut* sample: **149.4 / 130.9 / 95.7** for 5 / 50 / 150 mm | The fraction of the information in the usable events that the estimator actually extracts (η = 1 means bound-saturating) | same + audit_kinematics |
| **Θ_exp (exposure-normalized)** | `sigma_theta * sqrt(n_total) = Θ / sqrt(eps)`. The acceptance eps is 0.996 / 0.700 / 0.077 | The operational, detector-level number. It folds in the prompt-cell veto ("containment penalty inversion", Fig 4). | production_exposure, gabe exposure |
| **N for 1°** | `N_1deg = Θ^2`, `n_total,1deg = Θ_exp^2` | The headline physics number: how many IBDs are needed for sub-degree pointing | derived |
| Bias / linearity | `<theta_hat − theta_true>` over the full 360° | Systematic error. It matters once σ is below 1°. | angle_sweep_full360 |
| Isotropy | max/min of `sigma_theta(theta_true)` | Lattice (C4) artifacts | angle_sweep_full360 |
| Critical occupancy ρ_c | the `rho = N/G^2` where Θ leaves its plateau (claimed ρ_c ≈ 1) | When FND/EMD on a fine mesh collapses ("sparsity trap") | unclipped_scaling, emd_sparsity |
| Smearing robustness | `Θ(sigma_smear) / Θ(0)` | Sensitivity to the detector's position resolution | smearing |

### Current values from Max's tables (N_usable around 10^4–10^5)

| dx | Θ0,cut | Θ Centroid (discrete) | Θ FND (parabolic) | Θ EMD (paired proxy) | η Cent / FND / EMD | Θ_exp Cent / FND |
|---|---|---|---|---|---|---|
| 150 mm | 95.7 | ~90–107 | ~115–180 | ~265–300 | ~0.9 / 0.3–0.7 / 0.1 | ~330–390 / 420–660 |
| 50 mm | 130.9 | ~115–165 | ~210–300 | ~390–510 | ~0.9 / 0.2–0.4 / 0.1 | ~135–195 / 255–360 |
| 5 mm | 149.4 | ~135–160 | ~690–900 | ~480–650 | ~1.0 / 0.03–0.05 / 0.05–0.1 | ~135–160 / 700–900 |

What the tables show: the centroid sits at the bound everywhere. FND and the EMD proxy are 1.5–6× worse in Θ, and much worse on a fine mesh.
Per *usable* event 150 mm is best. Per *total* event 5 mm is best, by about 2.4× in σ (about 6× in exposure). Max's own FoM tables don't yet
report errors, a per-pitch bound, or bias. Those gaps are what the CPU-node reruns need to close:

1. **Trial count.** K = 25 means σ itself is uncertain by `1/sqrt(2K)` ≈ ±14%, and η by about ±28%. The same quantity (centroid, 5 mm, N = 10k) comes out
   as Θ = 111, 140 and 191 in three different suites. Use K ≥ 200 (±5%) and report CIs on Θ and η.
2. **Bound.** The figure scripts hard-code `CRLB_CONST = 129.58` for every pitch. Use the per-pitch Θ0,cut above. Also note that `sigma_perp/r_bar`
   is the *centroid's* asymptotic error, not a true Fisher/CRLB bound for a non-Gaussian displacement distribution. That is why the centroid shows η ≥ 1 in places.
   A real CRLB, or an ML estimator, would be the honest reference.
3. **Bias.** In the 360° sweep the centroid returns −θ (issue 3). After flipping the sign, its bias is about 0.3–0.4°. FND carries a **1.0–1.9° bias**,
   which is larger than its σ at 150 mm (0.77°).
4. **EMD definition** (issue 1). All EMD numbers above come from a random-pairing proxy, so the EMD comparison in the paper isn't meaningful until
   a real W1 is used: exact OT via assignment/POT, or sliced/Sinkhorn W1, minimized over rotation φ. This is the most compute-heavy item.

## Issues found (raise with Max)
1. **None of the forms called "EMD" is the true 2D W1.** The core package's `wasserstein_distance(flat_k, flat_ref)` compares histogram *bin values* and ignores
   bin positions. Max's own README calls it legacy, but it still fills the EMD columns of the angle-sweep and count-scaling tables (constant EMD, std = 0).
   The production, unclipped, sparsity, smearing and Gabe suites use `mean(|R(phi) r_i − r0_i|)` with measurement and reference events **paired by random index**.
   That is an arbitrary coupling, so it is an upper bound on W1, not W1. `plot_l2_vs_fnd_vs_emd_v3` / `append_emd_to_pitch_sweep` combine the 1D W1 of the x and y marginals, which still only uses the marginals.
2. **`w1_audit_output.txt` Parts 2–4 used unpaired data.** They loaded `fid_captures.npy` alone, giving a raw sigma_perp of 11,546 mm instead of 44 mm. The centroid errors of 67–101° are artifacts,
   so its comparison against Table I isn't valid.
3. **The centroid sign bug is unfixed.** The "sign fix branch" (`v0_6_6_4_2_0`) is code-identical to `v0_6_6_4`. Across the full 360° sweep, `Cent_mean ≈ −theta_true`.
4. **Data pairing is fragile but correct.** The loader assumes `captures[3:]` lines up with `vertices[:]`. This was checked at the start, middle and end: offset 3 gives a median |d| of about 65 mm,
   while every other offset gives about 26 m. The last ~1M capture rows are unused.
5. **There are NaNs in several tables.** FND/EMD are skipped above N = 100k, and FND fails at very fine pitch. Watson U² is NaN without pycircstat2.

# 1. Project Overview

## 1.1. Description and Purpose

The `paper_c_stats_package_v0-5.ipynb` script is a post-processing and statistical analysis package designed to process raw tracking datasets generated by RATPAC2 Monte Carlo simulations. Its primary purpose is to convert raw ASCII simulation outputs—specifically tracking files such as `truth.txt` and `neutrons.txt`—into structured 2D spatial matrices for analysis. The package implements multiple statistical testing routines, spatial distance metrics, and parallel computing capabilities to evaluate detector sensitivity and pattern-matching behavior.

## 1.2. Evaluating Directional Capability of Inverse Beta Decay (IBD) Events

A central objective of this codebase is measuring the directional reconstruction capabilities of segmented scintillator detectors when observing Inverse Beta Decay (IBD) interactions.

Key functionalities included in this evaluation are:

* **Vertex and Capture Calculation:** Extracting prompt positron annihilation vertices and delayed neutron capture locations, then computing relative spatial offset coordinates.


* **Detector Lattice Segmentation:** Discretizing continuous interaction coordinates into 2D square grid segmentation arrays (e.g., $9 \times 9$ matrix grids with segment widths like $50\text{ mm}$) to model physical detector voxels.


* **Angular Sensitivity & Pattern Matching:** Rotating simulation datasets across discrete angle ranges (such as $[0^\circ, 45^\circ]$ or $[-180^\circ, 180^\circ]$) to compute distance metrics like the Frobenius Norm of Difference (FND) and Continuous FND (CFND) against reference datasets.


* **Statistical Sensitivity Mapping:** Fitting directional response distributions using Gaussian, absolute sine, and von Mises fits to determine angular uncertainty ($\delta\theta$) in low-count and varied segment regimes.

## 4.2. Pre-processed Numpy Arrays (`fid_vertices_0.npy`, `fid_captures_0.npy`)

To avoid re-parsing massive multi-gigabyte ASCII tracking text files during every execution run, the parallel pipeline provides a `processData()` method. This parses raw ASCII text once on the host node (`rank == 0`) and serializes the processed interaction coordinates into binary NumPy arrays:

* **`fid_vertices_0.npy`:** A structured $N \times 3$ NumPy array storing the prompt IBD interaction vertices `[mcx, mcy, mcz]` in millimeters.


* **`fid_captures_0.npy`:** An $N \times 3$ NumPy array storing the corresponding delayed neutron capture locations `[px, py, pz]` in millimeters.



When `readData()` executes, it loads these binary `.npy` arrays directly from disk and evaluates the relative displacement vectors ($\vec{\Delta r} = \text{captures} - \text{vertices}$). This drastically reduces I/O bottlenecking and speeds up execution during iterative angular rotations and shuffling routines.

## 5. Performance Expectations and Memory Management

The processing routines are engineered to handle computationally intensive Monte Carlo datasets, frequently scaling from 100,000 to over 10,000,000 simulated particle events. Because reading massive ASCII text logs line-by-line introduces severe input/output (I/O) bottlenecks, the pipeline relies on preprocessing raw tracking outputs into vectorized NumPy (`.npy`) binary arrays or structured Pandas DataFrames.

However, loading these entire structures into memory simultaneously can exceed available hardware resources. Below are the baseline memory expectations, hardware requirements, and execution time characteristics across the single-threaded and parallel processing tracks.

### 5.1. Hardware Requirements & Memory (RAM) Footprint

* **Small Datasets (<100k events):** Can be processed within standard desktop or laptop environments (8–16 GB RAM).


* **Standard Datasets (~1M events):** Consumes approximately 12–20 GB of active RAM during DataFrame instantiation. Standard free-tier cloud environments (e.g., free Google Colab with ~12 GB RAM) may encounter Out-Of-Memory (OOM) runtime errors. High-RAM Colab instances or local workstations equipped with at least 32 GB RAM are strongly recommended.


* **Large Datasets (10M+ events):** Memory footprint scales linearly to ~120–200 GB RAM. Processing full 10M-event datasets without batching requires execution on High-Performance Computing (HPC) nodes or high-memory server infrastructure.



### 5.2. Execution Times: Serial vs. Parallel Processing

* **Single-Threaded Track (Processor v2.1):** Suitable for interactive debugging, track visualization, and smaller datasets. Processing 1,000,000 events takes approximately 8–10 minutes.


* **MPI-Parallelized Track (v0.5):** Designed for multi-core workstations and cluster nodes. Distributing a 1,000,000-event workload across 4 CPU cores reduces execution time to approximately 2.5 minutes, yielding a ~3.2x computational speedup.

#### 1. Data RAM Footprint Estimation

Assuming an average of 100 interaction steps per simulated Inverse Beta Decay (IBD) event:

* **Variables Tracked:** `Row`, `trackTime`, `trackKE`, `trackPro`, `x`, `y`, `z` (7 primary numerical columns).


* **Data Precision:** 64-bit float / integer types consume 8 bytes per value.


* **Bytes per Interaction Step:** $7 \text{ columns} \times 8 \text{ bytes} = 56 \text{ bytes}$ (rounded to 64 bytes for array overhead).


* **Storage per Single Event:** $100 \text{ steps} \times 64 \text{ bytes} = 6,400 \text{ bytes } (\sim 6.4 \text{ KB})$.



**1 Million Events:**

* **Raw NumPy Array:** $1,000,000 \text{ events} \times 6.4 \text{ KB} \approx 6.4 \text{ GB}$.


* **Pandas Overhead:** Pandas DataFrames incur $2\times$ to $3\times$ memory overhead due to index structures, column metadata, and object pointers.


* **Total Estimated RAM:** **12 GB to 20 GB**.



**10 Million Events:**

* **Raw NumPy Array:** $10,000,000 \text{ events} \times 6.4 \text{ KB} \approx 64 \text{ GB}$.


* **Total Estimated RAM:** **120 GB to 200 GB**.



#### 2. Runtime Estimation (Serial vs. MPI)

Assuming an average processing time of 0.5 milliseconds per event for parsing, coordinate rotation, grid binning, and norm calculation on a standard CPU core:

* **Single-Threaded Execution (1M Events):**

$$t_{\text{serial}} = 1,000,000 \times 0.0005 \text{ seconds} = 500 \text{ seconds} \approx \mathbf{8.3 \text{ minutes}} \text{[cite: 4]}$$


* **4-Core MPI Parallel Execution (1M Events):**
Accounting for inter-process communication (IPC) overhead and scatter/gather synchronization using an 80% parallel efficiency factor ($\eta = 0.8$):

$$\text{Speedup} = N_{\text{cores}} \times \eta = 4 \times 0.8 = 3.2\times \text{[cite: 4]}$$


$$t_{\text{parallel}} = \frac{500 \text{ seconds}}{3.2} = 156.25 \text{ seconds} \approx \mathbf{2.6 \text{ minutes}} \text{[cite: 4]}$$

# 6. Core Modules & Architecture

## 6.1. Parallel Code Module using `MPI4PY` (Author: Jeffrey G. Yepez)

The parallel computing module utilizes `mpi4py` to distribute computationally intensive matrix rotation and Frobenius norm evaluation routines across multiple CPU cores.

```
┌─────────────────────────────────────────────────────────┐
│                    Host Node (Rank 0)                   │
│  - Loads & processes ASCII / .npy coordinates           │
│  - Executes sampleData() buffer shuffling               │
│  - Broadcasts data array to worker ranks via bcast()    │
└────────────────────────────┬────────────────────────────┘
                             │
            ┌────────────────┴────────────────┐
            ▼                                 ▼
┌─────────────────────────┐       ┌─────────────────────────┐
│      Worker Rank 0      │  ...  │      Worker Rank N      │
│  Evaluates θ = [-180, x]│       │  Evaluates θ = [y, 180] │
└───────────┬─────────────┘       └───────────┬─────────────┘
            │                                 │
            └────────────────┬────────────────┘
                             │
                             ▼
┌─────────────────────────────────────────────────────────┐
│                    Host Node (Rank 0)                   │
│  - Gathers FND calculations via comm.gather()           │
│  - Extracts argmin angle / performs curve fitting       │
│  - Fits von Mises distribution in calcUncertainty()     │
└─────────────────────────────────────────────────────────┘

```

### Key Architectural Features

* **Distributed Angular Allocation:** The total $360^\circ$ evaluation space ($[-180^\circ, 180^\circ]$) is dynamically split into sub-arrays across available MPI processes using `np.array_split()`.


* **Dynamic Data Buffer Shuffling (`sampleData`):** To prevent statistical oversampling when drawing iterative event samples ($n$), coordinates shift dynamically between a `main` array and a `buffer` array, swapping flow direction once the primary pool depletes.


* **Parallel Direction Reconstruction (`directionAlgorithm`):**
1. Rank 0 samples $2n$ events (half reference, half target) and broadcasts them to all worker processes using `comm.bcast()`.


2. Each rank rotates the target event coordinates across its assigned slice of angles, bins the events into an $N \times N$ grid, and calculates the discrete Frobenius Norm of Difference (FND).


3. Calculated FND values are gathered back to Rank 0 using `comm.gather()`.


4. Rank 0 finds the minimum norm via `np.argmin()` or fits an absolute sine curve (`abs_sine`) to identify the best directional match ($\hat{\theta}$).




* **Uncertainty Quantification (`calcUncertainty`):** Executes iterative Monte Carlo direction runs, wraps resulting angles into $( -180^\circ, 180^\circ ]$, fits a von Mises circular distribution (`scipy.stats.vonmises`), and extracts circular standard deviations ($\sigma_{\text{deg}}$).

## 6.2. Processor v2.0 and v2.1 (Gabe's Code)

The `Processor` modules provide single-threaded routines for data conversion, 2D detector grid modeling, 2D/3D event track rendering, and analytical benchmarking.

### Processor v2.0 Core Features

* **Pandas Data Ingestion (`initData`):** Reads space-delimited ASCII tracking data directly into Pandas DataFrames, grouping rows by `Row` (event ID) to isolate initial interaction vertices, neutron scattering steps, and capture locations.


* **Grid Geometry Initialization (`initGrid`):** Sets up a $2\text{D}$ square grid segmentation matrix (`self.seg`) defined by grid dimension $N \times N$ (`grid_size`) and voxel width $dx$ (`cube_size` in mm).


* **Discretized Event Binning (`binEvents`):** Rotates relative interaction vectors by angle $\theta$, injects uniform vertex position randomization inside the central segment to model spatial uncertainty, and populates discrete bin counts.


* **Frobenius Norm Analysis (`frobeniusNormAnalysis`):** Compares rotated bin matrices against reference distributions using discrete FND, applying localized Gaussian fits over minimum valleys to quote angular errors.


* **Visualization Tools:**
* `plotTracks2D` / `plotTracks3D`: Renders 2D projections and 3D spatial trajectories of positron tracks, neutron scatter paths, IBD vertices, and capture points.


* `neutronHistogram` / `positronHistogram`: Evaluates Euclidean track length distributions ($d_n$, $d_+$).


* `binDistColormap` / `cloudPlot`: Plots spatial coordinate hit density heatmaps and scatter clouds.





### Processor v2.1 Enhancements

Processor v2.1 extends v2.0 by introducing continuous analytical expressions and multivariate distribution modeling:

* **Continuous FND Analysis (`continuousFrobeniusNorm` & `CFNDAnalysis`):** Replaces discrete bin comparisons with continuous $2\text{D}$ double integrals using `scipy.integrate.dblquad` across symmetric multivariate normal distributions to eliminate binning artifacts:



$$\text{CFND} = \sqrt{\iint \left[ f_{\text{ref}}(x,y) - f_{\text{rot}}(x,y) \right]^2 dx \, dy} \text{[cite: 1]}$$


* **Analytical Closed-Form Evaluation (`CFND_eval_int`):** Integrates exact closed-form mathematical evaluations of the continuous norm difference to benchmark numerical quadrature methods.


* **2D Gaussian Surface Fitting (`normalDistFit`):** Fits binned $2\text{D}$ spatial capture distributions with continuous multivariate normal surfaces (`gaussian_2d`) to extract spatial standard deviations ($\sigma_x, \sigma_y$) and spatial centroids.

# 7. Analytical Methods & Algorithms

## 7.1. 2D Square Grid Detector Segmentation

To model physical segmented scintillator arrays, the package converts continuous 3D particle interaction coordinates into discrete 2D spatial hit distribution matrices.

### Grid Geometry & Boundary Calculations

The detector layout is parameterized by two variables:

* **`grid_size` ($N$):** The number of segment voxels along one side of the 2D grid matrix. This value **must be an odd integer** (e.g., $3 \times 3$, $9 \times 9$, $25 \times 25$) so that a uniquely defined central segment exists to represent the prompt Inverse Beta Decay (IBD) interaction vertex.


* **`seg_size` / `cube_size` ($dx$):** The physical width of an individual square segment in millimeters (e.g., $50\text{ mm}$ or $150\text{ mm}$).



The total half-width of the detector grid ($l$) is defined by:


$$l = \frac{N \cdot dx}{2}$$

For each cell $(i, j)$ in the $N \times N$ matrix (where $i, j \in \{0, \dots, N-1\}$), the spatial spatial boundaries $[x_{\text{low}}, x_{\text{high}}]$ and $[y_{\text{low}}, y_{\text{high}}]$ are defined relative to the central vertex as:


$$x_{\text{low}} = j \cdot dx - l, \quad x_{\text{high}} = (j + 1) \cdot dx - l$$

$$y_{\text{high}} = -(i \cdot dx - l), \quad y_{\text{low}} = -((i + 1) \cdot dx - l)$$

---

## 7.2. Direction Algorithm and Coordinate Rotation

### Relative Vector Transformation

For each IBD event, the relative neutron capture vector $\vec{\Delta r} = (\Delta x, \Delta y, \Delta z)$ is evaluated by subtracting the prompt positron vertex position from the delayed capture point:


$$\Delta x = x_{\text{capture}} - x_{\text{vertex}}, \quad \Delta y = y_{\text{capture}} - y_{\text{vertex}}$$

### 2D Spatial Coordinate Rotation

To test incoming antineutrino directionality, the code rotates relative 2D interaction vectors $(\Delta x, \Delta y)$ by a trial angle $\theta$. The rotation transformation is calculated as:


$$r = \sqrt{\Delta x^2 + \Delta y^2}, \quad \theta_0 = \operatorname{arctan2}(\Delta y, \Delta x)$$

$$\phi = -\frac{\theta \cdot \pi}{180}$$

$$x' = r \cos(\theta_0 - \phi), \quad y' = r \sin(\theta_0 - \phi)$$

Equivalently, using the 2D Euclidean rotation matrix:


$$\begin{pmatrix} x' \\ y' \end{pmatrix} = \begin{pmatrix} \cos\phi & -\sin\phi \\ \sin\phi & \cos\phi \end{pmatrix} \begin{pmatrix} \Delta x \\ \Delta y \end{pmatrix}$$

### Prompt Interaction Vertex Randomization

To account for spatial vertex resolution limitations inside physical detector cells during binning, `binEvents()` injects a uniform random offset $(x_{\text{rand}}, y_{\text{rand}})$ inside the central segment width $[-dx/2, dx/2]$ before binning:


$$x_{\text{binned}} = x' + x_{\text{rand}}, \quad y_{\text{binned}} = y' + y_{\text{rand}}$$

---

## 7.3. Frobenius Norm Difference (FND) and Continuous FND Analysis

### Discrete Frobenius Norm of Difference (FND)

The similarity between a target matrix $M_{\text{rot}}(\theta)$ and a baseline reference matrix $M_{\text{ref}}(\theta_0)$ is evaluated using the discrete Frobenius norm. Both matrices are first normalized by total hit count ($\sum_{i,j} M[i,j] = 1$):

$$\text{FND}(\theta) = \Vert{}M_{\text{ref}} - M_{\text{rot}}(\theta)\Vert{}_F = \sqrt{\sum_{i=0}^{N-1} \sum_{j=0}^{N-1} \left( M_{\text{ref}}[i,j] - M_{\text{rot}}[i,j] \right)^2}$$

The trial rotation angle that minimizes $\text{FND}(\theta)$ corresponds to the optimal predicted interaction direction $\hat{\theta}$:


$$\hat{\theta} = \operatorname{argmin}_{\theta} \text{FND}(\theta)$$

### Continuous Frobenius Norm of Difference (CFND)

To eliminate discrete grid binning artifacts and edge-truncation errors, Processor v2.1 implements a continuous $2\text{D}$ double integral evaluation over symmetric multivariate normal probability distributions $f(x,y;\theta)$:

$$\text{CFND}(\theta_0, \theta) = \sqrt{ \int_{-l}^{l} \int_{-l}^{l} \left[ f(x, y; \theta_0) - f(x, y; \theta) \right]^2 dx \, dy }$$

where $f(x, y; \theta)$ represents the continuous 2D spatial interaction probability density rotated by angle $\theta$. In code, this double integral is evaluated numerically using `scipy.integrate.dblquad`.

### Exact Closed-Form CFND Expression

For benchmarking quadrature integration methods, `CFND_eval_int` evaluates the exact analytical closed-form solution over symmetric Gaussian probability distributions:

$$\text{CFND}(\theta_0, \theta) = \sqrt{ \frac{1}{2\pi \sigma^2} \left( 1 - \exp\left[ \frac{\mu^2 (\cos(\theta_0 + \theta) - 1)}{2\sigma^2} \right] \right) }$$

where $\mu = \sqrt{\mu_x^2 + \mu_y^2}$ is the radial mean offset and $\sigma = \frac{\sigma_x + \sigma_y}{2}$ is the effective spatial spread.

---

## 7.4. Curve Fitting using Gaussian, Absolute Sine, and von Mises distributions

### Inverted Gaussian Valley Fitting

To extract the angular uncertainty ($\delta\theta$), a localized Gaussian curve is fitted directly over the inverted FND curve minimum:

$$g(\theta) = y_{\text{shift}} - A \exp\left( -\frac{(\theta - \mu)^2}{2\sigma^2} \right)$$

where $\mu$ is the reconstructed central direction $\hat{\theta}$, and $\sigma$ represents the fitted standard deviation. The statistical uncertainty in the angular estimate is computed as:

$$\delta\theta = \frac{\sigma}{\sqrt{N_{\text{fit}}}}$$

### Absolute Sine Global Fitting

Over the full $360^\circ$ angular domain, the FND profile exhibits characteristic periodic folded behavior. The package fits this global response using an absolute sine functional model:

$$f_{\text{sin}}(\theta) = A \cdot \left\vert{} \sin\left( \frac{(\theta - \theta_0) \cdot \pi}{360} \right) \right\vert{} + C$$

where $A$ is the amplitude, $\theta_0$ is the phase shift, and $C$ is the baseline vertical shift.

### Von Mises Circular Distribution Fitting

For iterative Monte Carlo trials in `calcUncertainty()`, reconstructed angles $\theta_i$ are converted to radians and fitted to a von Mises circular distribution using `scipy.stats.vonmises`:

$$f(\theta \mid \mu, \kappa) = \frac{\exp(\kappa \cos(\theta - \mu))}{2\pi I_0(\kappa)}$$

where $\mu$ is the mean circular direction, $\kappa$ is the concentration parameter, and $I_0(\kappa)$ is the modified Bessel function of order 0.

The circular standard deviation in radians ($\sigma_{\text{rad}}$) and degrees ($\sigma_{\text{deg}}$) is derived from the concentration parameter $\kappa$ using exponentially scaled Bessel functions ($I_1/I_0$):

$$R = \frac{I_1(\kappa)}{I_0(\kappa)} = \text{i1e}(\kappa) / \text{i0e}(\kappa)$$

$$\sigma_{\text{rad}} = \sqrt{-2 \ln(R)}, \quad \sigma_{\text{deg}} = \frac{180}{\pi} \cdot \sigma_{\text{rad}}$$

# 8. Visualization & Plotting

The package provides a comprehensive suite of visualization tools to analyze single-event particle trajectories, spatial hit topologies, kinematic spectrums, and binned detector cell responses.

---

## 8.1. 2D and 3D Track Plotting for Neutrons and Positrons

### 3D Track Reconstruction (`plotTracks3D`)

The `plotTracks3D` method extracts full step-by-step spatial trajectories for a specific event row from the parsed RATPAC2 dataset. All spatial coordinates are centered relative to the primary Inverse Beta Decay (IBD) interaction vertex `[mcx, mcy, mcz]`.

```python
proc.plotTracks3D(event=255, view=(20, 225, 0), save=True)

```

* **Method Parameters:**
* `event` (int): Event index matching the `Row` identifier in RATPAC2 ASCII tracking output.


* `view` (tuple): Elevation, azimuth, and roll angles `(elev, azim, roll)` for 3D camera orientation.


* `save` (bool): Exports figure to `track_plot_3d.pdf` when set to `True`.




* **Visual Elements:**
* **Black Scatter Point:** Primary IBD interaction origin $(0, 0, 0)$.


* **Red Solid Line & Marker:** Positron ionization trajectory terminating at the annihilation vertex.


* **Orange Solid Line & Marker:** Neutron scattering trajectory terminating at the final thermal capture location.





### 2D Orthogonal Projection (`plotTracks2D`)

The `plotTracks2D` method projects 3D interaction paths onto the transverse $(x, y)$ plane. This provides a high-resolution view of single-event spatial track topology and angular deflection prior to capture.

```python
proc.plotTracks2D(event=255, save=True)

```

---

## 8.2. Kinematic Histograms and Time Domain Graphs

### Track Length Distributions (`neutronHistogram` & `positronHistogram`)

Calculates the 3D Euclidean distance $d$ between particle interaction endpoints and the initial Monte Carlo truth vertex:


$$d = \sqrt{(\Delta x)^2 + (\Delta y)^2 + (\Delta z)^2} \text{[cite: 1]}$$

* **`neutronHistogram(save=False)`:** Plots the step histogram of neutron track lengths $d_n$ (for capture, 1st-scatter, or 2nd-scatter states) and outputs the calculated mean track length in mm.


* **`positronHistogram(save=False)`:** Evaluates $d_+$ for positron annihilation points relative to the IBD vertex (typically bounded within $0\text{--}50\text{ mm}$).



### Neutron Kinetic Energy Spectrum

Parses particle kinetic energies (`trackKE`) from RATPAC2 tracking logs to generate kinetic energy distributions for IBD neutrons:

* Filters out transport process artifacts (`trackPro != 4`).


* Converts kinetic energy to keV ($1000 \cdot \text{trackKE}$) and plots a 128-bin spectrum.


* Displays summary statistics overlay boxes containing mean energy and standard deviation ($\sigma_{\text{KE}}$).



### Time-Domain Energy Decay

Renders time-dependent thermalization decay curves for individual particle events:

* Plots kinetic energy `trackKE` (in keV) versus elapsed interaction time `trackTime` (in $\mu\text{s}$) on semilog axes.


* Evaluates step-by-step energy loss across successive elastic scatters prior to final nuclear capture.



---

## 8.3. Angular Distributions, Colormaps, and Cloud Plots

### Polar Angular Distributions (`angularDist`)

Evaluates the continuous 2D interaction azimuth angle $\theta = \operatorname{arctan2}(y, x)$ across the domain $[-\pi, \pi]$.

```python
proc.setKind("capture")
proc.angularDist(save=True)

```

* **Polar Formatting:** Uses 36 angular bins ($\Delta\theta = 10^\circ$) spanning $[-\pi, \pi]$.


* **Donut Chart Styling:** Sets a negative radial origin (`ax.set_rorigin(-hole_rad)`) to generate a clean central hole displaying the observed interaction state text label (e.g., "capture" or "1st scatter").



### Spatial Coordinate Scatter Clouds (`cloudPlot`)

Displays continuous 2D point cloud distributions of raw $(\Delta x, \Delta y)$ coordinates relative to the origin $(0, 0)$:

* Generates equal-aspect-ratio spatial scatter plots.


* Automatically adjusts spatial axis boundaries based on interaction state ($100\text{ mm}$ limit for captures vs. $20\text{ mm}$ for 1st-scatters).



### Spatial Grid Colormaps & Heatmaps (`binDistColormap` & `cmapPlot`)

Renders binned 2D spatial hit distributions across the $N \times N$ detector grid:

* **`binDistColormap(theta)`:** Bins events rotated by trial angle $\theta$ and renders an `imshow` heatmap using the `viridis` colormap. It dynamically overlays explicit integer hit counts inside each voxel cell, auto-adjusting text color (black/white) based on local bin density.


* **`cmapPlot()`:** Plots continuous 2D spatial density distributions using high-resolution 2D histograms (`hist2d`) with `gray_r` colormaps and colorbars.



### 3D Voxel LEGO Bar Plots (`gaussHist2D`)

Generates 3D bar plots ("LEGO plots") using Matplotlib `bar3d` to display discrete 2D spatial count distributions as volumetric column blocks:

* Parameterized by segment width (`seg_size`) and grid dimensions (`grid_size`).


* Sets 3D elevation and azimuth perspective angles (`elev=10`, `azim=30`) for spatial visualization of central prompt peak heights relative to neighboring voxels.

# 9. Statistical Testing Suite

Because segmented detector arrays produce truncated spatial distributions that may lack an assumed parametric functional form (such as a pure Gaussian or von Mises fit), the package includes a suite of non-parametric, distribution-free statistical tests. These methods evaluate flattened or $2\text{D}$ event matrices against rotated reference templates to isolate optimal angular matches ($\hat{\theta}$).

---

## 9.1. Goodness-of-Fit Tests

### 9.1.1. Kuiper Two-Sample Test

* **Implementation:** `funtest_kuiper_2()` utilizing `astropy.stats.kuiper_two`.


* **Methodology:** Evaluates cumulative distribution function deviations across $1\text{D}$ flattened hit vectors (`flat_measurement` vs. `flat_A`/`flat_B`).


* **Application:** Provides a rotation-invariant goodness-of-fit metric across candidate rotation angles, where smaller test statistics and $p$-values indicate closer directional alignment.



### 9.1.2. Kolmogorov-Smirnov (KS) Test

* **Implementation:** `funtest_ks()` utilizing `scipy.stats.ks_2samp`.


* **Methodology:** Computes the maximum vertical distance between empirical cumulative distributions of flattened detector matrices.


* **Application:** Serves as a standard non-parametric baseline to test whether an observed measurement array differs significantly from reference orientation templates.



### 9.1.3. Chi-Squared Test

* **Implementation:** `scipy.stats.chisquare`.


* **Methodology:** Evaluates bin-by-bin frequency differences between normalized observed arrays and expected theoretical matrices.


* **Application:** Requires probability normalization (`flat_measurement_normalized`) and an added epsilon factor ($\epsilon = 10^{-6}$) to avoid zero-count division errors in low-count voxels.



### 9.1.4. Anderson-Darling Test

* **Implementation:** `scipy.stats.anderson`.


* **Methodology:** An Empirical Distribution Function (EDF) test that places greater statistical weight on the tails of spatial distributions.


* **Application:** Evaluates empirical flattened arrays (`flat_A`, `flat_B`, `flat_measurement`), returning test statistics alongside critical values across standard significance levels.



---

## 9.2. Divergence & Distance Metrics

### 9.2.1. Earth Mover's Distance (Wasserstein Distance)

* **Implementation:** `scipy.stats.wasserstein_distance`.


* **Methodology:** Quantifies the minimum optimal transport "work" required to transform one spatial hit distribution into another.


* **Application:** Directly incorporates spatial coordinate geometry, measuring how far hit mass must move between physical voxels rather than evaluating bin counts independently.



### 9.2.2. Kullback-Leibler (KL) Divergence

* **Implementation:** `scipy.special.rel_entr`.


* **Methodology:** An information-theoretic measure evaluating relative entropy and information loss when approximating empirical distributions with reference models:



$$D_{\text{KL}}(P \parallel Q) = \sum P(i) \ln\left(\frac{P(i)}{Q(i)}\right) \text{[cite: 1]}$$


* **Application:** Evaluated on normalized spatial fields with an added $10^{-6}$ epsilon smoothing factor to guarantee numerical stability.



### 9.2.3. Jensen-Shannon Divergence

* **Implementation:** `scipy.spatial.distance.jensenshannon`.


* **Methodology:** A symmetric, bounded variation of KL divergence that provides a smooth, distance-like metric.


* **Application:** Avoids asymmetry issues when comparing normalized empirical measurement fields against pre-simulated reference grids.



### 9.2.4. Bhattacharyya Distance

* **Implementation:** Custom `bhattacharyya_distance()` helper function.


* **Methodology:** Measures the physical overlap of probability distributions across detector segments:



$$D_B(p, q) = -\ln\left(\sum \sqrt{p(i) \cdot q(i)}\right) \text{[cite: 1]}$$


* **Application:** Quantifies geometric intersections between observed and simulated interaction matrices.



---

## 9.3. Circular Statistics

### 9.3.1. V-Test

* **Implementation:** `pycircstat2.hypothesis.V_test`.


* **Methodology:** A modification of the Rayleigh test used to detect departures from circular uniformity when a specific direction angle is known *a priori*.


* **Application:** Evaluates circular objects (`Circular`) constructed from detector vectors, testing hypotheses against target angles (such as $0^\circ$ or $90^\circ$) to return $V$-statistics, $u$-scores, and $p$-values.



### 9.3.2. Watson $U^2$ Test

* **Implementation:** `pycircstat2.hypothesis.watson_u2_test`.


* **Methodology:** A non-parametric circular two-sample test that evaluates the mean square error between cumulative directional distributions.


* **Application:** Processes `Circular` objects weighted by integer IBD hit frequencies (`weights_M`, `weights_A`, `weights_B`), using weighted array expansions (`create_weighted_df`) to extract $U^2$ test statistics and $p$-values.



---

## 9.4. Permutation Testing and Mahalanobis Distance

### 9.4.1. Permutation Testing

* **Implementation:** `scipy.stats.permutation_test`.


* **Methodology:** A model-free resampling technique that shuffles data points across samples to establish empirical reference distributions.


* **Application:** Uses a mean-difference statistic function (`stat_func`) over $1000$ resamples to extract exact $p$-values, determining whether angular variations are statistically significant or driven by low-count noise.



### 9.4.2. Mahalanobis Distance

* **Implementation:** `scipy.spatial.distance.mahalanobis`.


* **Methodology:** Evaluates distance between multidimensional data vectors while factoring in spatial covariance:



$$D_M(\vec{x}, \vec{y}) = \sqrt{(\vec{x} - \vec{y})^T \mathbf{\Sigma}^{-1} (\vec{x} - \vec{y})} \text{[cite: 1]}$$


* **Application:** Accounts for directional correlations across spatial dimensions without needing to flatten 2D/3D detector matrix structures.

# 10. Future Work & Planned Improvements

While the current pipeline is fully functional for Google Colab environments, several architectural and documentation improvements are planned to make the codebase more robust, scalable, and accessible for broader collaborations.

## 10.1. Command-Line Interface (CLI) and Configuration Files

Currently, I/O paths (e.g., `/content/truth.txt`) and physical parameters like `grid_size` and `cube_size` are hardcoded directly within the class `__init__` methods.

* **Planned Improvement:** We plan to integrate `argparse` or a JSON/YAML configuration system. This will allow users to pass parameters dynamically from the command line (e.g., `python main.py --config settings.yaml --data /path/to/data.txt`) without needing to alter the underlying source code.



## 10.2. Architectural Refactoring & Namespace Management

To ensure a seamless "Run All" experience in Colab without namespace collisions, the single-file monolithic structure requires minor refactoring.

* **Planned Improvement:** Distinct class names will be implemented to separate the different processing architectures (e.g., renaming the MPI module to `MPITrackReconstructor` and the v2.1 module to `SerialTrackReconstructor`). A global unified configuration block will be added to the top of the script, acting as a control panel to toggle specific analysis routines on or off.



## 10.3. Expanded Local Execution Documentation

The current Quick Start guide focuses heavily on the Google Colab workflow.

* **Planned Improvement:** The README will be expanded to include explicit execution instructions for local and cluster environments. This will clarify when to run the script as a standard `.py` file (`python script.py`) versus how to invoke the parallel processing module (e.g., `mpiexec -n 4 python script.py`).



## 10.4. Performance Benchmarking & Memory Guidelines

The code handles computationally heavy Monte Carlo datasets, processing upwards of 1 million to 10 million events. Loading large Pandas DataFrames or massive NumPy arrays can lead to memory exhaustion on standard local machines.

* **Planned Improvement:** A "Hardware Requirements & Performance" section will be added to the documentation. This will detail the expected RAM footprint for various dataset sizes and provide runtime comparisons between the single-threaded (v2.1) and MPI-parallelized processing tracks.
